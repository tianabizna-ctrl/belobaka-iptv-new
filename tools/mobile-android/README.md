# BELOBAKA IPTV — Android build

The Android app is the Angular PWA (`apps/web`) wrapped in a
[Capacitor](https://capacitorjs.com) WebView, plus a native on-device FFmpeg
transcoder.

## Layout

| Path | Purpose |
| --- | --- |
| `capacitor.config.ts` (repo root) | Capacitor app id/name, `webDir`, cleartext + mixed content |
| `android/` (repo root) | Generated Gradle project (`cap add android`) |
| `tools/mobile-android/plugin/com/belobaka/iptv/` | Native sources copied into the Gradle project |
| `tools/branding/generate-belobaka-assets.mjs` | Generates every icon/splash from one vector source |

## Build

```shell
pnpm android:build        # nx build web --configuration=production && cap sync android && gradlew assembleDebug
# APK: android/app/build/outputs/apk/debug/BELOBAKA-IPTV.apk
```

The `applicationVariants` block in `android/app/build.gradle` renames the AGP
default output (`app-debug.apk` / `app-release.apk`) to `BELOBAKA-IPTV.apk` for
every build type.

`ANDROID_HOME` must point at an SDK with platform 35+ and build-tools (the local
machine uses `~/Library/Android/sdk`). `android/local.properties` records it.

### JDK: `jlink` must be a real binary

AGP's JDK-image transform runs `jlink --version`. Some JetBrains JBR installs
symlink `bin/jlink` to the macOS `/usr/bin/jlink` stub, which **hangs forever**
(and stalls the build at `:capacitor-android:compileDebugJavaWithJavac`). Build
against a JDK whose `jlink` is a real binary and pin it explicitly:

```shell
export JAVA_HOME="/Users/<you>/Library/Java/JavaVirtualMachines/jbr-21.0.11/Contents/Home"
export PATH="$JAVA_HOME/bin:$PATH"
./gradlew assembleDebug -Dorg.gradle.java.home="$JAVA_HOME"
```

Check with `"$JAVA_HOME/bin/jlink" --version` — it must print a version at once.
If the build ever stalls, look for a hung `/usr/bin/jlink` process.

## Native customizations applied after `cap add android`

1. `android/app/src/main/java/com/belobaka/iptv/LocalTranscoderPlugin.java`,
   `LocalTranscodeServer.java` and `ScreenOrientationPlugin.java` are copied
   from `tools/mobile-android/plugin/`. `MainActivity.onCreate` registers both
   plugins (`registerPlugin(...)`) **before** `super`.
2. `android/app/build.gradle` adds:
   - `dev.ffmpegkit-maintained:ffmpeg-kit-full:8.1.7` (LGPL FFmpegKit fork;
     same `com.arthenica.ffmpegkit` API; arm64-v8a + x86_64, 16 KB pages)
   - `org.nanohttpd:nanohttpd:2.3.1` (loopback server for the transcoded HLS)
3. `android/variables.gradle`: `minSdkVersion = 24` (FFmpegKit requires it).
4. `AndroidManifest.xml`: `INTERNET` permission, `usesCleartextTraffic="true"`
   (http IPTV providers + the loopback transcoder), hardware acceleration.
5. `res/values/strings.xml`: `app_name = BELOBAKA IPTV`.
6. Icons/splash generated by `tools/branding/generate-belobaka-assets.mjs`.
7. APK output renamed to `BELOBAKA-IPTV.apk` via `applicationVariants` in
   `android/app/build.gradle`.

## Portal transport (PWA vs Android)

In a hosted PWA, Xtream/Stalker requests are proxied through the
playlist-parser web backend (`corsProxyUrl`), because browsers cannot reach
plain-http portals from an https origin and many panels send no CORS headers.

The Android shell does not use that backend: inside the Capacitor WebView
`PwaService.forwardXtreamRequest` calls the portal **directly**
(`xtream-direct-transport.ts`). Xtream panels answer cross-origin requests
themselves (`player_api.php` echoes any origin; stream routes send
`Access-Control-Allow-Origin: *`), mixed content is `ALWAYS_ALLOW`, and a
direct call keeps portal credentials off third-party infrastructure. This
matters: the current hosted parser deployment answers `402 DEPLOYMENT_DISABLED`,
so any WebView relying on it could never open a portal.

Video playback and the on-device FFmpeg transcoder already fetch the stream
URLs directly from the WebView.

Not yet migrated to direct fetch (still proxy-dependent, untouched for the
embedded Xtream flow): Stalker portals and M3U-by-URL imports.

## Transcoding

`WebPlayerViewComponent` renders `app-transcode-panel` (in
`libs/ui/playback/src/lib/transcoding/`). The panel lists the phone resolution
ladder — 1920×1080, 1280×720, 1024×576, 704×576, 960×540, 854×480, 640×360,
426×240 and 256×144 — and, on selection, calls the native `LocalTranscoder`
plugin. The plugin runs FFmpegKit (hardware H.264
MediaCodec first, software `mpeg4` fallback), writes HLS (live) or MP4 (VOD)
under the app cache, and serves it over `http://127.0.0.1:<port>`.

The panel hides itself once a resolution is picked (it covers the top-right of
the player) and hands the loopback URL to the main player: `WebPlayerViewComponent`
computes an `engineStreamUrl` that becomes the loopback output while a session
runs for the current source, so the transcoded picture plays in the normal
engine, not in a small in-panel preview. A start that fails (or a runtime error
from the native listener) brings the panel back with the reason. The floating
launcher button fades out with the player chrome after a few idle seconds and
returns on any tap, staying put while its dialog is open.

The bridge is resolved lazily inside `TranscodingService`: an injected
`TRANSCODE_BRIDGE` wins when a host provides one, otherwise
`createCapacitorTranscodeBridge()` dynamically imports `@capacitor/core` and
registers the `LocalTranscoder` plugin. Nothing from the transcoding module (or
`@capacitor/core`) enters the initial bundle, and on any runtime where the
plugin is absent the panel renders nothing.

## Live view on touch screens

On a phone, and on any touch-first device up to 1024px wide, the Xtream live
layout gives the whole pane to the player and floats the lists over it as
translucent overlays: the rules live in `live-stream-layout.component.scss`
under `@media (max-width: 640px), (pointer: coarse) and (max-width: 1024px)`,
mirrored by `isLiveOverlayViewport()` in `@iptvnator/portal/shared/util`.

- The categories/channels rail is an overlay with a left-to-right dark
  gradient; picking a channel fades it away. Tapping the player, or the
  floating `chevron_right` handle, brings it back. The rail keeps its width
  while hidden, so its rows never reflow.
- The shell's own categories rail folds when a stream starts
  (`hideCategories('portal')`), so the channel-list header's category dropdown
  is the way back; its phone drawer is translucent.
- The EPG guide is an overlay too: a sheet across the bottom in portrait, a
  side panel on the right in landscape, so the player always keeps the pane.

Hidden-ness is transient and per-visit — the persisted sidebar level is
untouched, so a desktop visit is unaffected.

## Screen orientation

`ScreenOrientationPlugin` (`tools/mobile-android/plugin/`) switches the
activity to `SCREEN_ORIENTATION_SENSOR_LANDSCAPE` while a stream plays and back
to `UNSPECIFIED` when it stops, so the picture turns with the content. The web
half is `libs/ui/playback/src/lib/player-orientation.ts`
(`lockPlayerLandscape()` / `releasePlayerOrientation()`): it resolves
`@capacitor/core` lazily and no-ops outside the native WebView, so the desktop
web build is unaffected.
